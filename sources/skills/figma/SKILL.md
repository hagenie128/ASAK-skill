# Figma 전체 QA

## 호출 예시
- `피그마`
- `현재 파일만 검토해줘`
- `수정하지 말고 문제와 근거만 알려줘`
- `문제를 찾고 안전한 범위에서 수정한 뒤 검증해줘`

## 실행 절차
1. 프로젝트 공통 지침과 사용자 요청 범위를 확인한다.
2. 관련 파일, 호출 위치와 현재 동작을 먼저 찾는다.
3. 아래 점검 기준으로 문제와 근거를 확인한다.
4. 검토 전용 요청이면 파일을 수정하지 않는다.
5. 수정 요청이면 확인된 문제만 최소 범위로 수정한다.
6. 가능한 검증을 실행하고 미검증 항목을 분리해 보고한다.

## 점검 기준
- 프레임·컴포넌트·Variant·Property 이름과 재사용 구조를 확인한다.
- 색상, 폰트, 간격, Radius, Shadow 토큰의 일관성을 확인한다.
- Auto Layout, Hug/Fill/Fixed, Constraints와 반응형 동작을 확인한다.
- CTA, Header, Footer와 콘텐츠 기준선을 화면 간 비교한다.
- 선택·비활성·로딩·오류·품절·빈 상태와 접근성을 확인한다.

## 결과 형식
- 결론
- 확인한 범위와 파일
- 발견한 문제와 근거
- 수정한 내용 또는 수정 제안
- 검증 방법과 결과
- 남은 위험과 미검증 항목
- 공부 포인트

# 테스트 및 QA

## 호출 예시
- `테스트`
- `현재 파일만 검토해줘`
- `수정하지 말고 문제와 근거만 알려줘`
- `문제를 찾고 안전한 범위에서 수정한 뒤 검증해줘`

## 실행 절차
1. 프로젝트 공통 지침과 사용자 요청 범위를 확인한다.
2. 관련 파일, 호출 위치와 현재 동작을 먼저 찾는다.
3. 아래 점검 기준으로 문제와 근거를 확인한다.
4. 검토 전용 요청이면 파일을 수정하지 않는다.
5. 수정 요청이면 확인된 문제만 최소 범위로 수정한다.
6. 가능한 검증을 실행하고 미검증 항목을 분리해 보고한다.

## 점검 기준
- 정상, 경계, 오류, 회귀 테스트를 구분한다.
- 빈 값, 잘못된 값, 연속 클릭, 새로고침, 뒤로 가기와 네트워크 실패를 포함한다.
- 각 수동 QA 항목에 사전조건, 단계, 기대 결과를 작성한다.
- 자동 테스트와 수동 시각 QA를 분리하고 우선순위를 표시한다.
- 기존 테스트를 삭제하거나 약화하지 않고 실패 원인을 먼저 분석한다.

## 결과 형식
- 결론
- 확인한 범위와 파일
- 발견한 문제와 근거
- 수정한 내용 또는 수정 제안
- 검증 방법과 결과
- 남은 위험과 미검증 항목
- 공부 포인트

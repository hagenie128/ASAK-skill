# 데이터베이스 점검

## 호출 예시
- `DB`
- `DB - 현재 파일만`
- `DB - 수정하지 말고 문제만 알려줘`
- `DB - 문제를 찾고 안전한 범위에서 수정해줘`

## 실행 절차
1. 프로젝트 공통 지침을 읽는다.
2. 관련 파일과 호출 흐름을 먼저 찾는다.
3. 아래 기준에 따라 검사한다.
4. 수정 요청이 있으면 최소 범위로 수정한다.
5. 가능한 검증을 실행한다.
6. 쉬운 한국어로 결과를 보고한다.

## 점검 기준
- PK, FK, UNIQUE, NULL, DEFAULT와 인덱스를 확인한다.
- 중복 컬럼과 파생값 저장 여부를 확인한다.
- 재료, 옵션, 알레르기, 품절 책임이 적절히 분리됐는지 확인한다.
- CASCADE는 데이터 손실 위험을 설명하고 임의 적용하지 않는다.

## 결과 형식
- 결론
- 확인한 파일
- 발견한 문제
- 수정한 내용
- 확인한 방법
- 남은 위험
- 공부 포인트

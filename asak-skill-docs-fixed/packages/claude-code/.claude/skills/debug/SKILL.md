# 버그 원인 추적

## 호출 예시
- `버그`
- `현재 파일만 검토해줘`
- `수정하지 말고 문제와 근거만 알려줘`
- `문제를 찾고 안전한 범위에서 수정한 뒤 검증해줘`

## 실행 절차
1. 프로젝트 공통 지침과 사용자 요청 범위를 확인한다.
2. 관련 파일, 호출 위치와 현재 동작을 먼저 찾는다.
3. 아래 점검 기준으로 문제와 근거를 확인한다.
4. 검토 전용 요청이면 파일을 수정하지 않는다.
5. 수정 요청이면 확인된 문제만 최소 범위로 수정한다.
6. 가능한 검증을 실행하고 미검증 항목을 분리해 보고한다.

## 점검 기준
- 증상, 기대 결과, 실제 결과와 재현 경로를 먼저 정리한다.
- 콘솔, 네트워크, 로그, 상태 변화와 호출 흐름을 근거로 가설을 세운다.
- 가능성이 높은 원인부터 하나씩 검증하고 추측성 수정을 피한다.
- 최소 수정 후 동일한 재현 경로로 다시 확인한다.
- 가능하면 회귀 테스트를 추가하고, 불가능하면 수동 재현 절차를 남긴다.

## 결과 형식
- 결론
- 확인한 범위와 파일
- 발견한 문제와 근거
- 수정한 내용 또는 수정 제안
- 검증 방법과 결과
- 남은 위험과 미검증 항목
- 공부 포인트

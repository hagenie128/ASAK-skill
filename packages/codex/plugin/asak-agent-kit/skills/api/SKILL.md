# API 연결 점검

## 호출 예시
- `API`
- `현재 파일만 검토해줘`
- `수정하지 말고 문제와 근거만 알려줘`
- `문제를 찾고 안전한 범위에서 수정한 뒤 검증해줘`

## 실행 절차
1. 프로젝트 공통 지침과 사용자 요청 범위를 확인한다.
2. 관련 파일, 호출 위치와 현재 동작을 먼저 찾는다.
3. 아래 점검 기준으로 문제와 근거를 확인한다.
4. 검토 전용 요청이면 파일을 수정하지 않는다.
5. 수정 요청이면 확인된 문제만 최소 범위로 수정한다.
6. 가능한 검증을 실행하고 미검증 항목을 분리해 보고한다.

## 점검 기준
- 요청 URL, HTTP 메서드, 헤더, 쿼리, body와 DTO를 실제 구현 기준으로 비교한다.
- 성공·검증 실패·인증·인가·서버 오류 상태 코드와 응답 형식을 확인한다.
- 로딩·빈 상태·네트워크 오류·timeout·재시도·요청 취소 흐름을 확인한다.
- 토큰 만료와 갱신 실패, 중복 요청, 비동기 응답 경합을 확인한다.
- 금액·수량·권한처럼 신뢰할 수 없는 값은 서버에서 다시 검증하는지 확인한다.

## 결과 형식
- 결론
- 확인한 범위와 파일
- 발견한 문제와 근거
- 수정한 내용 또는 수정 제안
- 검증 방법과 결과
- 남은 위험과 미검증 항목
- 공부 포인트

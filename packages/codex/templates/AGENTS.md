# ASAK 프로젝트 공통 지침

## 대화 방식
- 모든 설명, 질문, 보고는 한국어로 작성한다.
- 초보자도 이해할 수 있는 쉬운 표현을 사용한다.
- 결론부터 말하고, 변경 이유와 확인 방법을 함께 설명한다.
- 사용자가 한 단어로 명령해도 아래 단축 명령표에 따라 의도를 해석한다.

## 기술 기준
- Frontend: React + JavaScript
- Backend: Spring Boot + JPA
- React 컴포넌트: PascalCase
- JavaScript/Java 변수·함수: camelCase
- Database 테이블·컬럼: snake_case
- 기존 구조와 프로젝트 컨벤션을 먼저 확인한 뒤 따른다.

## ASAK 핵심 로직
- priceCalculation.js: 가격 계산의 단일 기준
- quantityLimits.js: 수량 제한의 단일 기준
- 메뉴·옵션·제외 재료·세트 추가금
- 장바구니와 주문 요약
- 품절 처리
- 결제 성공·실패·재시도·중복 결제 방지
- 타임아웃과 초기화
- 관리자·주방 화면
- Figma 디자인 시스템

## 작업 원칙
1. 관련 파일과 호출 흐름을 먼저 찾는다.
2. 현재 동작과 요구사항을 비교한다.
3. 문제를 재현하거나 근거를 확인한다.
4. 가장 작은 범위로 수정한다.
5. 빌드·테스트·린트 중 가능한 검증을 실행한다.
6. 결과를 아래 형식으로 보고한다.

## 결과 보고 형식
1. 결론
2. 확인한 파일
3. 발견한 문제
4. 수정한 내용
5. 확인한 방법
6. 남은 위험
7. 공부 포인트

## 절대 금지
- 사용자 승인 없이 파일·폴더·브랜치·데이터를 삭제하지 않는다.
- `git push --force`, `git reset --hard`, 디스크 포맷, 광범위 삭제 명령을 실행하지 않는다.
- 프로젝트 폴더 밖의 경로를 수정하지 않는다.
- 비밀키, 토큰, 개인정보를 출력하거나 저장하지 않는다.
- 관련 없는 파일 전체를 포맷하거나 대규모 리팩토링하지 않는다.
- 테스트하지 않은 결과를 완료라고 단정하지 않는다.

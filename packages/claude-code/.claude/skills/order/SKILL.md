# 주문 흐름 점검

## 호출 예시
- `주문`
- `현재 파일만 검토해줘`
- `수정하지 말고 문제와 근거만 알려줘`
- `문제를 찾고 안전한 범위에서 수정한 뒤 검증해줘`

## 실행 절차
1. 프로젝트 공통 지침과 사용자 요청 범위를 확인한다.
2. 관련 파일, 호출 위치와 현재 동작을 먼저 찾는다.
3. 아래 점검 기준으로 문제와 근거를 확인한다.
4. 검토 전용 요청이면 파일을 수정하지 않는다.
5. 수정 요청이면 확인된 문제만 최소 범위로 수정한다.
6. 가능한 검증을 실행하고 미검증 항목을 분리해 보고한다.

## 점검 기준
- 홈→목록→상세→장바구니→결제→완료 흐름을 실제 라우팅과 상태 기준으로 추적한다.
- 뒤로 가기, 옵션 재수정, 새로고침 시 상태 유지와 복구 여부를 확인한다.
- 빈 장바구니, 품절 변경, 가격 변경, 결제 실패·취소·재시도를 확인한다.
- 연속 클릭, 중복 주문, 중복 결제를 막는 멱등성 기준을 확인한다.
- 타임아웃 후 주문·개인정보·임시 상태가 안전하게 초기화되는지 확인한다.

## 결과 형식
- 결론
- 확인한 범위와 파일
- 발견한 문제와 근거
- 수정한 내용 또는 수정 제안
- 검증 방법과 결과
- 남은 위험과 미검증 항목
- 공부 포인트

# 배포 전 최종 점검

## 호출 예시
- `배포`
- `현재 파일만 검토해줘`
- `수정하지 말고 문제와 근거만 알려줘`
- `문제를 찾고 안전한 범위에서 수정한 뒤 검증해줘`

## 실행 절차
1. 프로젝트 공통 지침과 사용자 요청 범위를 확인한다.
2. 관련 파일, 호출 위치와 현재 동작을 먼저 찾는다.
3. 아래 점검 기준으로 문제와 근거를 확인한다.
4. 검토 전용 요청이면 파일을 수정하지 않는다.
5. 수정 요청이면 확인된 문제만 최소 범위로 수정한다.
6. 가능한 검증을 실행하고 미검증 항목을 분리해 보고한다.

## 점검 기준
- 빌드, 테스트, 린트를 가능한 범위에서 실행한다.
- TODO, console.log, 임시 데이터, 하드코딩 URL, 비밀값과 환경 설정을 확인한다.
- 주문·가격·수량·품절·결제·타임아웃 핵심 흐름을 확인한다.
- 치명적·높음·보통·낮음으로 우선순위를 나누고 배포 차단 항목을 구분한다.
- 배포 명령, migration, 외부 설정 변경과 롤백 절차는 승인 전 실행하지 않는다.

## 결과 형식
- 결론
- 확인한 범위와 파일
- 발견한 문제와 근거
- 수정한 내용 또는 수정 제안
- 검증 방법과 결과
- 남은 위험과 미검증 항목
- 공부 포인트

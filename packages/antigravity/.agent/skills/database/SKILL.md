# 데이터베이스 점검

## 호출 예시
- `데이터베이스`
- `현재 파일만 검토해줘`
- `수정하지 말고 문제와 근거만 알려줘`
- `문제를 찾고 안전한 범위에서 수정한 뒤 검증해줘`

## 실행 절차
1. 프로젝트 공통 지침과 사용자 요청 범위를 확인한다.
2. 관련 파일, 호출 위치와 현재 동작을 먼저 찾는다.
3. 아래 점검 기준으로 문제와 근거를 확인한다.
4. 검토 전용 요청이면 파일을 수정하지 않는다.
5. 수정 요청이면 확인된 문제만 최소 범위로 수정한다.
6. 가능한 검증을 실행하고 미검증 항목을 분리해 보고한다.

## 점검 기준
- PK, FK, UNIQUE, NULL, DEFAULT, CHECK와 인덱스를 확인한다.
- 중복 컬럼, 파생값 저장, 다대다 관계와 책임 분리를 확인한다.
- 재료, 옵션, 알레르기, 품절, 주문 데이터의 정합성을 확인한다.
- CASCADE, DDL, migration은 데이터 손실·잠금·롤백 위험을 먼저 설명한다.
- 인덱스는 실제 조회 조건과 정렬 기준을 근거로 제안하고 무분별하게 추가하지 않는다.

## 결과 형식
- 결론
- 확인한 범위와 파일
- 발견한 문제와 근거
- 수정한 내용 또는 수정 제안
- 검증 방법과 결과
- 남은 위험과 미검증 항목
- 공부 포인트

# Spring Boot/JPA 점검

## 호출 예시
- `백엔드`
- `현재 파일만 검토해줘`
- `수정하지 말고 문제와 근거만 알려줘`
- `문제를 찾고 안전한 범위에서 수정한 뒤 검증해줘`

## 실행 절차
1. 프로젝트 공통 지침과 사용자 요청 범위를 확인한다.
2. 관련 파일, 호출 위치와 현재 동작을 먼저 찾는다.
3. 아래 점검 기준으로 문제와 근거를 확인한다.
4. 검토 전용 요청이면 파일을 수정하지 않는다.
5. 수정 요청이면 확인된 문제만 최소 범위로 수정한다.
6. 가능한 검증을 실행하고 미검증 항목을 분리해 보고한다.

## 점검 기준
- Controller, Service, Repository와 도메인 책임 분리를 확인한다.
- Entity 직접 노출, DTO 변환, Validation과 예외 응답 일관성을 확인한다.
- 트랜잭션 범위, 지연 로딩, N+1, 불필요한 쿼리와 동시성 문제를 확인한다.
- 상태 변경·삭제·조회 시 인증과 인가가 서버에서 검증되는지 확인한다.
- 중복 요청과 결제·주문 API의 멱등성, 로그의 민감정보 노출을 확인한다.

## 결과 형식
- 결론
- 확인한 범위와 파일
- 발견한 문제와 근거
- 수정한 내용 또는 수정 제안
- 검증 방법과 결과
- 남은 위험과 미검증 항목
- 공부 포인트
